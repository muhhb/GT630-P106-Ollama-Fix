解决GT630与P106双卡模式下ollama的问题
GT630与P106显卡双卡运行ollama时ollama一直调用GT630问题解决方案
 
问题现象
 
双卡环境（2GB显存GT630 亮机输出卡 + P106 纯计算魔改卡）部署 Ollama 本地AI大模型时：
Ollama 默认优先调用GT630进行AI推理，哪怕是2G版本GT630，7B模型依旧容易爆显存OOM报错，模型启动失败，完全不调用性能更强的P106计算卡。
 
GT630包含费米(Fermi)、开普勒(Kepler)两个硬件版本，本方案对这两个架构全部生效。
 
⚠️重要说明：该方法适用于全部Windows电脑，不限主板、CPU硬件，但重启电脑配置会全部失效，属于临时调试方案，重启后需要重新执行从第三步往后的操作。
 
适用环境
 
- 硬件：不限主板、不限CPU；
​
- 输出显卡：2GB显存GT630（费米 / 开普勒架构均支持），负责画面输出
​
- 计算显卡：P106‑100（雨糖科技475魔改驱动，无视频输出，专职AI计算）
​
- 系统：Windows10 / Windows11 全版本
​
- 软件：Ollama本地大模型
 
完整操作步骤（严格按顺序执行，全程断网！）
 
第一步：DDU彻底清理所有NVIDIA显卡驱动
 
1. 电脑进入安全模式
​
2. 打开DDU工具，设备类型选择GPU，厂商选择NVIDIA
​
3. 执行「清除并关机」，彻底删除驱动文件、注册表缓存。
 
第二步：GT630替换为微软基础显示驱动
 
1. 开机进入系统，保持断开网络，禁止Windows自动下载驱动。
​
2. 打开设备管理器→显示适配器，右键GT630 → 更新驱动程序 → 浏览我的计算机以查找驱动程序 → 让我从计算机上的可用驱动程序列表中选取 → 选择微软基本显示适配器完成安装。
 
效果：GT630保留桌面画面输出，CUDA计算能力被彻底屏蔽，Ollama无法识别这张显卡作为计算设备。
 
第三步：安装雨糖科技475魔改驱动
 
1. 直接运行雨糖科技P106‑475驱动安装包，完全跟随驱动包本身的提示操作，按照安装向导下一步走完，证书、选项全部以驱动程序向导为准。
 
不要自己跳过或者手动干预弹窗，驱动程序让你做什么就做什么。
此时P106的CUDA计算功能正常启用。
 
第四步：回退适配GT630驱动状态
 
专门针对GT630做驱动适配微调，保证桌面分辨率、画面输出稳定，双卡功能互相隔离，不产生CUDA冲突。
 
⚠️核心注意事项（必阅）
 
1. 该方案为临时调试手段，一旦电脑重启，全部驱动配置失效！
重启后Windows会重置显卡驱动状态：GT630恢复N卡驱动、P106魔改驱动失效，需要重新执行【第三步、第四步】恢复环境。
​
2. 操作全程必须断开网络，联网Windows会自动下载官方N卡驱动，直接覆盖微软基础驱动，修复直接作废。
​
3. 雨糖驱动：一切以驱动包安装向导提示为准，跟随程序指引操作。
​
4. 关闭Windows设备自动安装驱动：此电脑右键→属性→高级系统设置→硬件→设备安装设置，选择：否，从不安装来自Windows更新的驱动软件，只能降低复现概率，不能阻止重启后的驱动重置。
​
5. 本方案同时兼容费米、开普勒两个版本2G‑GT630亮机卡。
 
✅修复成功验证标准
 
1. PowerShell执行 nvidia‑smi ，列表内仅出现P106，看不到GT630显卡。
​
2. Ollama加载模型， ollama ps PROCESSOR列显示GPU推理，不再占用大量CPU。
​
3. 7B模型加载不再报显存溢出OOM，生成token速度显著提升。
 
方案原理
 
Windows系统下多张NVIDIA显卡共存时，会优先把承担画面输出的显卡选为首选CUDA设备，和主板、CPU型号无关。
本方案使用微软基础驱动屏蔽GT630的CUDA算力，仅保留画面输出，强制系统内只有P106一张可用CUDA显卡，解决Ollama乱调用显卡爆显存的问题。
 
局限：Windows底层机制限制，该配置无法永久保存，重启丢失状态。适合调试、测试使用。
 
补充说明
 
- 适合场景：本地调试Ollama、测试P106算力、录制教程视频。
​
- 不适合：需要长期不间断开机、频繁重启主机的生产使用。
​
- 如果需要长期稳定双卡环境，需要研究显卡硬件ID屏蔽、VBIOS修改等进阶方案。
